Protocol Flow

One order → distributed into shards → autonomously allocated → converging to one deterministic condition
Order Initialization

Buyer submits an order.
Funds are locked in escrow.
↓
Order Sharding

The order is decomposed into multiple shards.
Number and volume are randomly generated.

Sharding occurs before any execution path selection.
↓
Protocol Allocation Engine

Each shard is independently routed by the protocol.
No actor decides allocation.

Shards are distributed across:

• Bootstrap Channel → VRS expansion
• Internal Channel → VRS-native exchange

Allocation criteria:
• vault reinforcement
• integration of new vaults
• optimization of reserve distribution

Execution is shard-based, not order-based.
↓

Bootstrap Path

VRS Layer Construction
External Issuer = Physical Seller
Case 1: issuer buys gold → capital exposure
Case 2: issuer already owns gold → onboarding
Transport assigned by protocol
Vault custody + Auditor verification
Validator checks certificates
VRS expands

Internal Path

VRS-Native Exchange
Internal Issuer = Protocol Function
Seller already owns VRS-backed assets
Order Sharding (common step)
Shard Matching (non-linear)
Case 3: buyer becomes future seller
Audit + validation checks
Ownership reallocation (no physical move)
Common Final Condition
I(sᵢ) = 1 ⇔ Valid(sᵢ)
Issuance depends only on validity.
Not on execution path.
The protocol emits the final token.
The issuer does not emit currency.

External issuer = asset provider
Internal issuer = execution function
