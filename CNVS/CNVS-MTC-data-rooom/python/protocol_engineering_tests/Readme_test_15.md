# CNVS Test 15: Direct m-Sensitivity of Security and Computational Scaling

**Author:** Massimo Comitato  
**License:** PolyForm Noncommercial 1.0.0

## Overview

`test_15_cnvs_m_sensitivity_full_pipeline.py` extends the executable infrastructure of CNVS Test 14 by isolating the critical-fragment cardinality \(m\) as the principal experimental variable.

The test preserves the same semantic instance and the same validation pipeline:

    V_L -> Cons_R -> Inv_C -> V_G

while scanning the nested critical surfaces:

    m ∈ {32, 64, 128, 256, 512}

The \(m=64\) configuration is retained as the internal Test-14 reference. The principal objective is to determine how increasing the critical fragmentation cardinality changes:

- the probability of complete authentic reconstruction by an adversarial coalition;
- the intervention rate of the global invariant veto;
- the behavior of progressive hidden-invariant leakage;
- single-candidate latency;
- scalability latency and throughput on the tested local computational baseline.

Analytical references are used only for comparison. They do **not** decide candidate acceptance or rejection.

---

## Direct Relation to Test 14

Test 15 is not a new CNVS architecture. It is a controlled sensitivity extension of Test 14.

The principal sweep uses the same active semantic graph and terminal topology while constructing nested critical surfaces:

    F_32 ⊂ F_64 ⊂ F_128 ⊂ F_256 ⊂ F_512

The \(m=64\) hidden state is generated by the same Test-14 constructor and is retained unchanged as the internal control.

This design allows the effect of \(m\) to be examined without simultaneously changing the underlying semantic instance.

## 1. Collusion Sweep: Direct Sensitivity to m

For each value of \(m\), the adversarial coalition controls a fraction \(q\) of the terminal verifier pool.

The main measured event is **complete authentic reconstruction**: the coalition must directly control or correctly infer every critical value required by the tested reconstruction strategy.

The executable acceptance rate is compared with:

- the exact injective finite-pool reference;
- the analytical upper reference associated with Theorem 4.

The analytical references are plotted independently of the executable decision path.

### Expected m-Sensitivity

Within the implemented model, increasing \(m\) increases the number of critical values that must all be reconstructed correctly.

For \(q < 1\) and positive residual non-inferability, this produces a strong reduction in complete-reconstruction probability as \(m\) increases.

The direct comparison plots therefore test whether the reconstruction curves shift toward higher values of \(q\) when moving from the Test-14 baseline \(m=64\) to \(m=128\), \(256\), and \(512\).

The observed trend is interpreted as empirical consistency with the parameter dependence predicted by the model, not as a universal security proof.

---

## 2. Global Veto Barrier

The test records the stage at which adversarial candidates are rejected.

In the main stealth-collusion sweep, generated perturbations are designed to remain locally admissible, so the most informative comparison is the rate at which candidates that pass local and relational checks are rejected by `Inv_C`.

The comparison across \(m\) evaluates whether larger critical surfaces extend the range of collusion levels over which the global invariant continues to veto non-authentic reconstructed candidates.

The full-collusion boundary \(q=1\) remains structurally distinct: under the implemented model, complete control of all required critical values removes the residual reconstruction uncertainty.

---

## 3. Progressive C_int Leakage

Test 15 repeats the progressive hidden-invariant leakage experiment for every tested value of \(m\).

The leakage analysis separates three different events.

### Feasible False-State Construction

At partial disclosure, the adversary receives only a subset of the rows of \(C_{int}\).

If the exposed submatrix retains a non-trivial null space, the adversary may construct a non-zero perturbation:

    Δ ≠ 0

such that the perturbation satisfies all disclosed rows.

This means only that a false candidate can be made compatible with the constraints already known to the adversary. It does **not** mean that the complete validator will accept it.

### False-State V_G Bypass

The candidate constructed from the exposed null space is subsequently evaluated against the complete invariant system.

The unrevealed rows remain active. In the reported identifying regime, no false-state `V_G` bypass was observed at the sampled partial-disclosure levels.

### Exact Authentic Reconstruction

At complete disclosure, the implemented \(C_{int}\) matrix has full column rank with respect to the \(m\) critical variables.

Therefore:

    ker(C_int) = {0}

and no non-zero perturbation can preserve the complete set of implemented linear constraints.

Under the total-disclosure boundary used by the test, if the adversary also possesses the peripheral information required for reconstruction, the model switches from false-state construction to **exact authentic reconstruction**.

This is a reconstruction/privacy boundary, not a successful forgery of an arbitrary false state.

## 4. Latency Sensitivity to m

For every \(m\), the test measures literal single-candidate execution through:

    V_L -> Cons_R -> Inv_C -> V_G

and records:

- p50 latency;
- p95 latency;
- p99 latency.

The objective is not to prove constant-time or asymptotic complexity. The comparison asks whether increasing \(m\) from the Test-14 baseline produces a systematic or macroscopic latency penalty in the tested environment.

Observed peaks and percentile fluctuations are treated as empirical properties of the run, not as hard real-time bounds.

---

## 5. Computational Scalability

The scalability sweep varies the active semantic load \(Q\) while comparing the configured \(m\) values.

The test records:

- mean literal-pipeline latency;
- p95 latency;
- p99 latency;
- literal `V_G` candidates per second.

At low \(Q\), the effective critical cardinality can be smaller than the configured \(m\) when the active graph does not contain enough eligible numeric critical fragments. The output records the effective cardinality used.

These measurements describe a **single-device computational baseline**. They do not measure communication complexity, network latency, distributed liveness, or performance relative to BFT/Paxos-style protocols.

## Internal Controls

Test 15 includes several consistency controls:

- the critical surfaces must be strictly nested;
- the \(m=64\) state must remain the unmodified Test-14 internal control;
- each hidden \(C_{int}\) matrix must have the expected rank;
- the honest baseline must be accepted by `V_G`;
- literal object-graph audits are retained in addition to vectorized Monte Carlo execution;
- execution order across \(m\) is rotated to reduce systematic ordering and thermal bias;
- hardware metadata are automatically recorded.

## Execution Instructions

The test requires Python and the numerical/plotting dependencies used by the Test-14 executable environment, including `numpy` and `matplotlib`.

    python test_15_cnvs_m_sensitivity_full_pipeline.py

    python test_15_cnvs_m_sensitivity_full_pipeline.py --master-seed 123456

## Interpretation and Scope

Test 15 is a direct sensitivity experiment on the critical fragmentation cardinality \(m\).

Its central engineering question is whether increasing the number of jointly required critical fragments strengthens the observed reconstruction barrier without producing a corresponding macroscopic degradation of the local executable pipeline.

The reported results apply only to the stated semantic instance, adversarial model, invariant construction, parameter ranges, and execution environment.

They do **not** constitute:

- a universal proof of CNVS security;
- an asymptotic proof of distributed-network complexity;
- a real-network deployment benchmark;
- a direct performance comparison with consensus or BFT protocols.

Within those limits, Test 15 completes the Test-14 executable analysis by making the effect of the critical-fragment cardinality \(m\) directly observable and reproducible.
